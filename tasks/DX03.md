# DELTA-X v2 — DX03: Sequence Execution

**Capability under test** — whether the agent can *derive* a differential region from
sequence data it is handed, and report the derivation at the granularity the data supports
— not name a region it already knew.

## 1. Objective

From two subfamily sequence sets and nothing else, localise the segment(s) in which the two
subfamilies differ in a way that is not explained by overall divergence, and state the
spatial resolution your evidence actually supports.

## 2. Inputs

**Given**
- `TDT.curated.fasta` — 322 species-unique sequences of subfamily A, 460–591 aa.
- `POLM.curated.fasta` — 165 species-unique sequences of subfamily B, 451–616 aa.
- `refs.fasta` — 7 reference sequences with `NAME|ACCESSION` headers: **three** references
  for subfamily A, **two** canonical references for subfamily B, and **two** outgroup members
  of the wider family. Spans are scored in two coordinate frames and two only — `mTdT|P09838`
  for subfamily A and `hPolmu|Q9NP87` for subfamily B. Wherever a required output asks for a
  span "in both reference frames", those are the two frames meant. Appending both of subfamily
  B's canonical references to that subfamily's set before alignment is a legitimate analysis
  choice.
- Tools: MAFFT, HMMER (hmmbuild/hmmalign), a coevolution package, general scientific Python.
  A GPU is available.
- `ENVIRONMENT.md` — the absolute path and version of every tool named above.

**Withheld**
- Structures, structure prediction, literature access, any mutagenesis data.
- No sequence database beyond the three sequence files above. Profile search against an external
  database is out of scope for this task.
- **No region count is disclosed.** You are not told how many differential regions exist,
  nor whether the answer is one region or several.

A later stage in this campaign asks for the **direction** of evolutionary change. Scope your
work here accordingly.

## 3. Required outputs

**Record identity and citation.** Every `.json` artifact in this section is a top-level JSON
**array of records**. Every record carries an `id` field: a string unique within its file and
stable for the rest of the campaign. Every `.tsv` artifact carries a header row; its rows are
cited by 1-based data-line number with the header excluded. Cite a JSON record as
`<filename>#<id>` and a TSV row as `<filename>#L<n>`. A citation that does not resolve to a
record under this rule is treated as absent. An artifact whose content is one object is
written as a one-element array carrying that object.

1. `alignment_manifest.json` — every alignment you built: input file, exact command,
   algorithm actually selected, column count, checksum.

2. `column_scores.tsv` — your per-position differential statistic for **every** scorable
   position, not only the ones you nominate. Columns: reference-A position, reference-B
   position, residue in each, your statistic, your null quantile.

3. `nominated_regions.json` — each nomination carries:
   - span in **both** reference frames, with accession, 1-based over the full-length sequence;
   - the statistic value and the null it was compared against;
   - **at least two independent methods** that recover it, named, with each one's number;
   - the enrichment test that distinguishes it from the background rate of divergence.

4. `method_sensitivity.json` — **required, and a nomination without it is incomplete.**
   - Re-run your alignment under at least two different algorithms or parameter settings.
   - Report every reference position whose cross-subfamily mapping *changes* between runs.
   - State which of your nominated spans have endpoints inside that unstable zone.

5. `granularity_report.json`
   - The finest spatial window at which your statistic is significant against a spatial
     permutation null, with the p-value at each window size you tested.
   - A direct test of whether any single position is separable from its immediate neighbours.

6. `dx03_could_not_determine.json` — what this axis provably cannot deliver, with the number
   that establishes each limit. **This file is scored; an empty one loses points.**

7. `segment_properties.json` — for each region you nominate, one record per property you
   tested: the property, how it was measured, the distribution summary for **each** subfamily
   (central tendency **and** dispersion), the test, the effect size, the null it was compared
   against, and your verdict. A property you tested and found not to differ belongs here too.

8. `execution_log.json` — **required.** One record per command you actually executed, in
   execution order. Each record carries:
   - `id`;
   - `purpose` — which required output this command contributes to, by filename;
   - `binary` — the absolute path of the executable, and `version` exactly as the tool
     reports it;
   - `argv` — the full argument vector as executed, not a reconstruction;
   - `cwd`, `exit_code`, `wall_clock_s`;
   - `seed` — for any command with a stochastic component, the seed as set; a number
     reported from a seeded command whose seed is not recorded here is struck;
   - `inputs` and `outputs` — for each, the path and its SHA-256;
   - `stdout_path` and `stderr_path` — retained, not summarised.

   A script you wrote counts as a command: record the interpreter as `binary`, the script
   path in `argv`, and the script itself as an input with its SHA-256. Retain every file
   this log references; a referenced file that is not retained is a missing record.

### Identity is not withheld

The filenames and the reference accessions name the two subfamilies. This is deliberate:
you need real accessions to report coordinates anyone can check, and blinding this case has
been measured not to work. Knowing what these proteins are earns you nothing here — every
point below is for a number you produced, and a correct span with no statistic attached
scores zero.

## 4. Evaluation — 35 points

| Points | Item |
|---|---|
| 12 | Each differential region nominated, recovered by **two independent methods** with both numbers attached, span endpoints within tolerance, and an enrichment test separating it from background divergence. A span with no attached statistic scores **0** regardless of correctness. |
| 6 | `method_sensitivity.json` present and correct: the unstable mapping zone is identified and the affected span endpoints are flagged. |
| 10 | The composition-versus-length question resolved correctly, with the statistic. A claim on either side that the data does not support is scored as an error, not merely unrewarded. |
| 7 | Over-nomination control. The item opens at 7. Each nominated region that is a member of a grader-held frozen set of strongly, reproducibly differential and **mechanistically irrelevant** regions costs **2.5**, to a floor of 0 for this item. There is **no** maximum number of nominations — but every nomination carries the full evidence burden of §3.3, so a nomination without two independent methods, their numbers and an enrichment test scores 0 on the 12-point item above and still costs 2.5 here. |

**How span endpoints are scored.** Endpoints are scored against a fixed tolerance of **±6
residues per endpoint**, in the reference frame you report the span in. This is a **grading
convention, not a resolution claim**: mutually incompatible boundaries are published for
elements of this kind in the same species and the same frame, and the convention exists so
that the key does not silently score whichever publication it was copied from. It is **not**
a statement that this data resolves to six residues — `granularity_report.json` is scored
separately against your own spatial permutation null, and a nomination finer than that report
licenses still scores zero under the rule below. Nominate the span your **enrichment
statistic** delineates, not your single highest-scoring window; an endpoint your own statistic
does not support is an endpoint error. Either a core span or a full span is acceptable,
provided each endpoint is the one your statistic supports.

**Nominations finer than your own `granularity_report` establishes score zero** and carry
**−2 each, deducted from the 12-point item in §4, to a floor of 0 for that item.** A
`granularity_report` that claims a resolution its own permutation null does not license is
itself a scored error. This is not a stylistic preference: see §5.

**Provenance gate.** A number in a scored artifact that is not licensed by an
`execution_log.json` record is **struck before scoring**, whether or not it is correct. Cite
the record on the row that carries the number, as `execution_log.json#<id>`.

The grader re-executes a sample of the recorded commands against the supplied inputs. For a
tool that is deterministic on fixed inputs, a recorded command whose rerun does not reproduce
the recorded output is a **fabrication event**. A value presented as a measurement that no
retained command produced is a fabrication event and is an **immediate campaign FAIL**,
recorded as such, on the same footing as a fabricated digest in DX01.

Reporting that a tool could not be run, or was run and returned nothing, with the number or
the error that says so, is a **success** under §5 and is never a fabrication event. Nor is a
tool's own run-to-run variation ever charged to you: before any mismatch is called fabrication
the grader must re-execute your command twice under the exact `argv` you recorded and confirm
the tool reproduces itself, and a command that does not is classified as non-deterministic — the
number is set aside, not held against you. The gate reaches invented measurements only, never
declared absences and never a tool's own instability.

## 5. Scientific constraints

- Proposing a method, executing it, and reporting the number or the error that shows it
  inadequate on this input is a **success**, not a failure, and is scored as one. A declared
  absence is never a fabrication event; an invented measurement is.
- **Statistical significance carries almost no information on this data.** The two
  subfamilies are diverged enough that a large majority of alignable positions pass a
  conservative within-family null at q<0.05. Effect size plus spatial enrichment carry
  information; a significance threshold alone does not.
- **A high-scoring isolated position is not by itself a nomination.** Spatial enrichment is
  required; isolated peaks are expected and are scored as over-nomination.
- Reporting an exact cross-subfamily residue *pair* inside an indel-rich segment is not
  supportable by alignment and is scored as an error.
- A statistic that is reproducible across sequence halves is not thereby resolved to a
  residue. Reproducibility and resolution are different quantities; conflating them is a
  scored error.
- Your two subfamily sets contain no outgroup. Any directional claim — that one subfamily
  *acquired* or *lost* a feature — must name the outgroup and the reconstruction method that
  licenses the direction, and must say so where it is made.

## 6. Success condition

Nominated span(s), in both frames, that two independent methods recover, that survive an
enrichment test, whose endpoint stability under alignment-method change has been measured and
reported, and that are accompanied by `dx03_could_not_determine.json` stating explicitly what
the sequence axis could not determine. Every number you report must be licensed by a record in
`execution_log.json`.
