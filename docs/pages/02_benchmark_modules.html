EVALUATION TAXONOMY

同一篇论文，需要三种不同 benchmark

LEVEL 1

Workflow reproduction

Agent 得到目标、指定方法、输入数据与严格输出格式；评分计算结果的正确性、完整性和可复现性。

侧重：科研编程和工具执行
LEVEL 2

Evidence interpretation

方法可由 Agent 自选；需识别关键观察、控制混杂、比较替代机制并提出合理解释。

侧重：生物物理分析与科学推理
LEVEL 3

Mechanism discovery

仅给研究现象和可用资源；Agent 自主提出假说、选择实验、利用新结果调整路线，最终建立证据链。

侧重：自主研究决策和可证伪机制

同一个 Agent 即使能复现所有 9 个工作流，也未必具备自主发现机制的能力。对高级任务，应隐藏已发表解释，并要求预注册下一实验的鉴别预测。

SCORING CONTRACTS

推荐的双层评分：结果正确性与科研决策

L1–L2 · artifact-grade

自动评分器

输出类型适合的指标
数值 CSV键覆盖、单位、MAE/相关性、分布一致性、重复区间
结构 / 轨迹原子映射、CV、RMSD、接触距离、状态占比、bootstrap CI
模型或事件图边集合 precision/recall、事件次序、时间不确定性
模拟 FES标定差值、峰/谷及 barrier、收敛、物理校验

数值容差应从独立实现和自然实验变异估计，不能随意以原论文数字作绝对标准。

L3 · discovery-grade

机制发现过程评分

评测对象审查问题
假说是否覆盖合理替代、包含可证伪条件？
实验计划预期结果能否区分候选机制；控制是否充分？
证据更新方向与强度是否依观察更新；是否留存冲突？
机制图是否解释各步事件，有哪些缺口/反证？
未来预测对未展示的突变体/同源酶是否产生可检验预测？

科学理由需有证据指针；专家评审可用于判断解释质量，但原始计数和数值计算采用独立自动验证。

BENCHMARK PACKAGE FORMAT

一个任务应该交付哪些文件？

目录为提议的 BixBench3-style 包装样例，不宣称与官方代码的运行接口直接兼容。

四项必需的评测契约

  1. 输入边界：Agent 能看到哪些原始数据、哪些工具、哪些知识。
  2. Artifact schema：列、单位、行键、null 规则、依赖顺序、重复识别。
  3. Hidden gold：参考输出及产生过程保存在 evaluator 侧。
  4. 评分协议：可接受误差、反证规则、缺测容忍度、专家复核。

不能把论文已经绘好的 FES 曲线作为输入，再按同一曲线评分；这只会测量读图或复制能力。

QUALITY AND CONTAMINATION

真正发布前需要解决的关键问题

标签和数据泄漏

公开题名、酶名、PDB ID、完整序列或 Zenodo 均可能使 Agent 直接检索到原论文结论。需要设计封闭 retrospective track 与保密 prospective track。

评分不能追认假说

只按与原文最终机制一致程度评分，会奖励猜测和背诵。需在结果揭示前固定预测、对照和成功判据。

重复的定义

3 个模拟随机种子是采样重复，来自同一晶体或原始样品的派生图表不构成独立生物重复。谱系应该传递到评分器。

反证与部分完成

失败的计算和 null 结果必须保留；如果系统发现竞争机制也能解释数据，应因恰当保留不确定性得到奖励。
