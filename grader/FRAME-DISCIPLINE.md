# Frame discipline — making a coordinate claim self-verifying

> **Paths.** This document was written against the private working tree. On release `agent_facing/` became `tasks/` and `repro/data/` became `data/`; nothing else moved. See `docs/PATH-MAP.md`. The text is otherwise unedited.

**CONTAINMENT.** Designer-side. Nothing here may be rendered into an evaluated agent's
context. A harness that does so voids its run.

Proposed 2026-11-09. **Status: specification, not yet measured.** No submission has been
graded under it. It changes a gate and two artifact schemas; it does not move any weight.

---

## 1. What was proposed, and what this key already rejected

The proposal: defeat recitation by **shifting residue numbering** in the served data, then
requiring the agent to **declare which numbering it used** and to **give the actual amino-acid
sequence** of the span rather than only its integers.

The middle of that is already settled and must not be reopened. `KEY.md`, *Method-sensitivity
zone*, records the decision:

> *"This replaces an artificial numbering offset. A memorised answer cannot produce a
> sensitivity measurement; it can only produce a span."*

and `DX03.md`, *Identity is not withheld*, records why the data is served unblinded:

> *"you need real accessions to report coordinates anyone can check, and blinding this case has
> been measured not to work."*

**An artificial shift of the served FASTA is rejected and stays rejected**, for two reasons
that have not changed:

1. **It is undone by the thing it is meant to catch.** An agent that remembers the canonical
   sequence recovers the shift by aligning the served record against memory — one step, no
   tool required for a 500-residue protein it has seen thousands of times.
2. **It breaks checkability.** The case's coordinates are its interface to the literature and
   to every structure record. Serving a private frame makes every reported integer
   unverifiable by anyone who was not handed the shift.

## 2. What survives, and why it is a different mechanism

The two halves the earlier decision did **not** cover are the declaration and the residue
string. They do not try to *hide* the frame; they make the claim **carry its own frame and its
own evidence**, so that the grader can check it against the served file mechanically.

The gap is concrete and currently asymmetric. `DX03.md` §3.2 (`column_scores.tsv`) already requires the *unscored*
per-column dump to carry residues:

> `column_scores.tsv` — *"reference-A position, reference-B position, **residue in each**, your
> statistic, your null quantile"*

while §3.3, the **scored** nomination, carries only integers:

> *"span in both reference frames, with accession, 1-based over the full-length sequence"*

**The scored object is less self-verifying than the dump beside it.** A nomination of
`376–400` is a claim no one can check without re-deriving it; a nomination of `376–400`
carrying `GQLDE…` either matches the served record at those indices or it does not.

## 3. The design

### 3.1 Three frames per nomination, not one

Every positional claim declares `frame_kind` and reports the span **and its residues** in each
of three frames:

| frame | what it is | who can produce it |
|---|---|---|
| `ref_A` | mTdT `P09838`, 1-based, full length | anyone with the served FASTA — **or with memory** |
| `ref_B` | hPolmu `Q9NP87`, 1-based, full length | same |
| `aln` | **column indices in the agent's own deposited alignment** | **only an agent that ran the alignment** |

`aln` is the load-bearing one, and it is the proposal's invariance trap in the form that
survives §1. It is a frame the agent **manufactures**, so:

- it cannot be recited — no training corpus contains this run's column indices;
- it is already deposited with a checksum (`DX03.md` §3.1), so the grader can project it;
- it genuinely differs between runs, and *most* inside the answer: three coordinate routes
  agree on **398/499** residue pairs protein-wide (79.8%) but only **6/26 (23%)** inside
  mTdT 378–403 (`KEY.md`, *Method-sensitivity zone*).

The shift the proposal asks for therefore already exists in the data. It is not injected by the
designer, it is generated by the agent's own method, and it is largest exactly where the answer
is. It only has to be **required as an output**.

### 3.2 The residue string, and the check it enables

Each frame's entry carries `sequence`: the exact residues at `[start, end]` **in that frame**.
The grader then runs a check that needs no judgement:

```
served[ref_A][s_A : e_A]              == seq_A          # served file
served[ref_B][s_B : e_B]              == seq_B          # served file
ungap(deposited_aln[cols_s : cols_e]) ⊇ {seq_A, seq_B}  # the agent's own alignment
```

A claim that fails any line is **struck before scoring**, exactly as an unlicensed number is
struck under the provenance gate — and for the same reason: the agent is reporting a span it
did not read.

### 3.3 The constant-offset detector — the actual trap

This is the part that discriminates, and it costs nothing to run.

The mTdT → hPolmu offset is **measured and non-constant** (`KEY.md`, *Offsets are not
constant*): `+0` at 1, `+5` at 29, `+2` at 97, `+12` from 150, `+13` from 283, `+15` from 358,
`+16` from 398, `+19` at 418 — and **inside the loop it swings +15 → +18 → +15 across mTdT
358–396**.

So for a span that spans that swing, a derived pair of coordinates has

```
(s_B − s_A)  ≠  (e_B − e_A)
```

and a pair produced by converting one frame to the other with a single offset has them
**equal**. Define the reported-only diagnostic

```
frame_offset_delta = (e_B − e_A) − (s_B − s_A)
```

`frame_offset_delta = 0` on a span crossing the swing is the signature of a constant-offset
conversion. It is not proof of recitation — it is a flag that the cross-frame mapping was
asserted rather than computed, which §3.4 then adjudicates.

The baseline makes this worth instrumenting: **2/3 of the clean-room runs volunteered a
constant-offset intuition** (`KEY.md`: *"0/3; 2/3 volunteered a CONSTANT-offset intuition"*),
`run1_s3.md:18` giving it as *"plausibly 0 or ±1 across the Loop1 region"* while declining to
state a rule. The failure this detects is one the model has already been observed to have.

### 3.4 Cross-frame mappings must be computed

Any `ref_A ↔ ref_B` correspondence carries an `execution_log` record for the alignment that
produced it. A mapping asserted without one is struck. This is the provenance gate applied to
a *correspondence* rather than to a number, and it is the clause that turns `frame_offset_delta`
from a curiosity into an adjudicable finding.

## 4. Where it attaches, task by task

- **DX01** — `DX01.md` §4 already scores numbering uncertainty as *declare, do not resolve*,
  and the baseline produced residue integers **0/3**, which is the design working. Frame
  discipline is the DX03-side **discharge** of that declaration: DX01 says "I cannot state a
  conversion rule", DX03 then has to show the conversion it actually used. No change to DX01
  beyond a forward reference.
- **DX03** — the main attachment. §3.3 gains `frame_kind`, `sequence` and the `aln` entry;
  §4 gains the strike rule. **The ±6 tolerance becomes frame-anchored rather than
  frame-dependent**: the grader aligns the reported `sequence` to the key's canonical span and
  scores the derived endpoints, so an agent is never penalised for which frame it chose. This
  also closes an open item — the three clean-room runs used three mutually incompatible
  canonicalisation recipes, which made their commitments incomparable.
- **DX04** — this is where frame discipline is **already** a scored item and nobody called it
  that. The 8-point `SEQRES` discrimination is a frame problem: PDB *author* numbering,
  `SEQRES` index and UniProt index are three frames, and "deleted from the construct" versus
  "present but disordered" is the question *which frame does this residue exist in*. Requiring
  the residue string makes the distinction mechanical instead of narrative: a residue absent
  from `SEQRES` has no string to report.
- **DX05** — inherits. A synthesis sentence citing a span inherits that span's frame record;
  a struck span strikes the sentence, as now.

## 5. What this does not fix

Stated plainly, because the page this feeds states its limits.

1. **It does not make recitation impossible.** An agent can align served-to-remembered and
   translate. The mechanism makes that step **explicit, logged and checkable** instead of free
   and invisible. It converts a shortcut into an artifact.
2. **Its discriminating power decays on publication.** "Declare the frame and read the string
   out of the file" is a cheap behaviour to learn, costs an honest agent nothing, and once
   learned is indistinguishable from derivation on the self-consistency check alone. Only the
   `aln` frame and the execution log keep discriminating after that, which is why the `aln`
   frame is the load-bearing one and not the residue string.
3. **It adds no points.** All three clauses are gates. Giving points for declaring a frame
   would pay for form again — the error this benchmark removed from DX01 and from the
   provenance gate.
4. **`frame_offset_delta` has a false-positive mode.** A span wholly inside one constant
   stretch has `delta = 0` legitimately. The diagnostic is only interpretable on spans crossing
   a change point, and the grader must state which change points the span crosses before
   reading it.

## 6. Open, before this can be adopted

- Decide whether `aln` is **required** or **required-when-an-alignment-was-run**. Required is
  cleaner but makes DX03 unanswerable without MAFFT, which is already true in practice but is
  not currently written as a hard dependency.
- Fix the canonicalisation recipe for the alignment digest **in the brief**. Three legal
  recipes produced three digests over the same four files; `aln` indices are only checkable
  against a deposited alignment the grader can reproduce byte-for-byte.
- Pick the tolerance semantics for string matching: exact match, or match modulo the
  `method_sensitivity` unstable zone. Exact is simpler and defensible, since the string comes
  out of a file the agent was handed.
- Decide whether `frame_offset_delta` is reported-only (recommended, like
  `delta_over_prior`) or feeds the existing strike rule via §3.4.
